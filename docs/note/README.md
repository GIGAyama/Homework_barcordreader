# note 入稿メモ（宿題ポスト）

このフォルダの中身は、note の連載「教室で使えるかもしれないもの作り」へ入稿するための一式です。

```
docs/note/
├── shukudai-post-note-article.md   記事本文。そのまま note に貼れます
├── images/                         実際にアプリを操作して撮った画面 25 点
└── README.md                       このファイル
```

---

## 1. 貼るまえに直すところ

### ⚠️ 連載番号

タイトルの `#◯` は埋めていません。過去の連載番号を確認できなかったため、
推測で入れると番号が飛んだり重なったりするおそれがあります。
**ここだけ、公開前に正しい番号へ書きかえてください。**

```
# 教室で使えるかもしれないもの作り #◯ 「宿題出した？」を毎朝聞いて回らない。……
```

### 公開前に反映してほしい修正

撮影中に、レポートの提出率が実態より低く出る不具合を見つけました。
記事とは別のコミットに分けてあります。

- コミット `fix(report): 月の途中で出したレポートの提出率が実態より低く出る問題を直す`
- 集計期間の既定は「今月の1日から末日」なので、月の途中で保護者面談サマリーを印刷すると、
  まだ来ていない日まで未提出として数えられていました
- デモ学級（28名・6月11日時点）で `14/65回・22%` と出ていたものが、正しくは `14/27回・52%` です
- 記事の画像 `25-report-print.png` は修正後の状態で撮り直しています

保護者へ渡す資料に関わるところなので、**記事より先に本番へ反映することをおすすめします。**

## 2. note に貼る手順

1. note で新しい記事を作り、`shukudai-post-note-article.md` の中身をそのまま貼る
2. 1行目の `# 教室で使えるかもしれないもの作り #◯ …` を、note のタイトル欄へ移す。
   本文からはこの行を削除する
3. 本文中の `![…](images/xx-….png)` の行を、note の画像ブロックに置きかえる。
   画像は手動アップロードが必要です。下の対応表の順に上から入れていけば、本文の並びと一致します
4. 画像の直後にある一行は、note のキャプション欄へ移す
5. ハッシュタグ欄に `#GIGAスクール` `#小学校教師` `#働き方改革` `#ICT教育` `#宿題` あたりを入れる
6. 見出しは note が自動で目次にします。`##` の並びがそのまま骨格になります

Markdown は見出しだけを使っています。太字、斜体、表、区切り記号は入っていません。
note のエディタに貼ったときに崩れるところは無いはずです。

## 6. 撮り直すときの手順

撮影に使ったスクリプト（デモ学級を組み立てるもの、画面をたどるシナリオ、
画像を整えるもの）は `.tmp-shots/` に置いて作業し、納品時に削除しました。
リポジトリには残していないので、撮り直すときは同じ組み立てからやり直すことになります。
土台は note-article スキルの `scripts/` にあります。

```bash
npm i --no-save playwright
npm run build

# 本番と同じサブパスで配る
node <skill>/scripts/serve.mjs dist 4180 /Homework_barcordreader/

# 別のターミナルで。シナリオは撮りたい画面に合わせて書く
node <skill>/scripts/capture.mjs <シナリオ> \
  --base http://127.0.0.1:4180/Homework_barcordreader/ --out <出力先>
```

撮影のときに気をつけたところを、いくつか残しておきます。ここを外すと本番と違う絵になります。

- **文字の書体**。このアプリは Google Fonts から丸ゴシックを読みます。
  撮影する環境から届かないと、端末に入っているゴシック体になり、本番と見た目が変わります。
  書体のファイルを `dist/fonts/` へ落としてから撮りました
- **印刷レイアウト**。保護者面談サマリーの紙面は印刷のときだけ表示される作りです。
  ブラウザの印刷プレビューと同じ状態に切りかえてから撮っています
- **端末の日付**。前章のとおり、木曜の朝にそろえています
- **縦に長い画面**。ビューポートを伸ばして1枚に収め、下に残ったべた塗りの余白を切り落としています

## 7. 文体について踏襲したこと

連載の書き方に合わせ、次のところを守っています。

- 太字、斜体、表、区切り記号（矢印やスラッシュやコロン）を使わない
- Markdown は見出しだけ。箇条書きは手順のところだけ
- デプロイ、ローカルストレージ、キャッシュといった言葉を使わず、
  「公開の設定」「その端末の中だけに残ります」と言いかえる
- 絵文字は見出しだけ。本文には入れない
- 子どものことは「子どもたち」。「児童」は本文では使わない
- 見出しは基本の6本に、このアプリの目玉として2本を足した構成
  （🌙 おやすみ日の提案、🤝 児童支援と家庭連携）
- 効果は言い切らず、作者の見立てとして書く
- **教室での出来事を実体験としては書いていません。** この記事は実践記録ではないので、
  「使ってみたら子どもたちが〜」に当たる記述は入れていません。
  実際の授業での様子は、公開前に書き手が足すところとして空けてあります
